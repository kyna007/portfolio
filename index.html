SQLHQL데이터 아키텍처요구사항 정의 (RE)도메인 커뮤니케이션
문제 정의
분산된 레거시(Legacy) 데이터 테이블의 정합성이 매우 낮아 비즈니스 지표 분석 시 오차가 발생했으며, 부서 간 데이터 기준(Silo)이 불일치했습니다.
데이터
  • 상품 마스터 레거시 데이터
  • 운영팀 기준 작업 데이터
  • 비즈니스 결합·수요 데이터
접근 방법
  • 현업 부서와의 도메인 커뮤니케이션·요구사항 정의(Requirements Engineering)로 데이터 기준 표준화
  • SQL·HQL 기반 레거시 데이터와 실무 데이터 간 정합성 교차 검증
  • 단일 진실 공급원(SSOT) 기반 신규 데이터 마트 설계 및 자동 적재 아키텍처 구축

02
LLM 활용 / 리소스 최적화

LLM(Claude Code) 기반 분석 요청 워크플로우 반자동화 및 운영 리소스 최적화

Claude Code (LLM CLI)PythonJira APIGitHubcrontab지식 자산화
문제 정의
반복적인 데이터 추출 및 분석 요청으로 인해 핵심 업무 병목이 발생했으며, 월 평균 약 42건의 요청을 한정된 인력(2~3명)이 처리하면서 운영 리소스의 비효율이 존재했습니다.
데이터
  • Jira 티켓 접수·처리 로그 (요청 유형 분류)
  • GitHub에 축적된 과거 티켓별 쿼리 이력
  • SQL 작성 팁·데이터 정책·지표 정의 Markdown 문서
접근 방법
  • 요청 유형별 티켓 분석으로 반복 성격의 워크플로우 식별
  • 티켓 설명에 '쿼리 요청' 등 지정 키워드가 포함된 티켓을 Jira API로 감지
  • GitHub에 축적된 과거 티켓 쿼리 중 가장 유사한 케이스를 찾아 참조
  • Markdown으로 정리한 SQL 작성 팁·데이터 정책·지표 정의를 함께 참고해 LLM이 쿼리 초안을 작성하고 Jira 댓글로 자동 등록
  • Claude Code로 설계한 Python 스크립트를 Mac crontab으로 설정한 주기마다 실행
  • GitHub·Markdown 기반 지속 학습 가이드를 구축해 팀 단위 지식 자산화 도입

경력·학력

쿠팡에서 리테일 운영 이슈 대응을 거쳐 프라이싱 Business Analyst로, 재직과 병행하며 빅데이터를 전공했습니다.
SQL 경험 없이 프라이싱 팀에 합류해 데이터 파이프라인 구축을 주도했고, AI를 독학해 팀의 Jira 워크플로우를 자동화했습니다.
